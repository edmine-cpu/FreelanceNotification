GitHub: `edmine-cpu/FreelanceNotification`; production-ветка — `main`.

## Работай по задаче

- Начни с `git status --short --branch`; сохраняй чужие изменения. Читай этот файл один раз за задачу.
- Ищи через `rg` в нужном модуле. Не перечитывай весь репозиторий, README и скиллы без необходимости.
- Карта кода: `app/telegram/` — команды и кнопки; `app/notifier/` — рассылка;
  `app/source/` — Freelancehunt API; `app/ai/` — генерация и цены;
  `app/storage/` — состояние пользователей; `app/config.py` — настройки;
  `deploy/` — автодеплой; `tests/` — unittest.
- Делай минимальную законченную правку. Не добавляй попутный рефакторинг,
  зависимости, новые инструменты, планы или субагентов для простой задачи.
- Используй уже настроенные окружение, SSH и деплой; не переустанавливай их для проверки.
  Независимые чтения объединяй, вывод ограничивай нужными строками.
- Уточняй только существенную неоднозначность или недостающий доступ.
  Уже разрешённые действия выполняй без повторного согласования.
- Для локальной правки документации достаточно проверки diff: не подключайся к VPS,
  не запускай сборку и тесты, не делай push только ради проверки текста.

## Проверки

- Для кода запускай относящиеся к изменению unittest в существующем Python-окружении.
  Полный набор при изменениях общего поведения: `python -m unittest discover -s tests -q`.
- Для механизма деплоя: `python3 -m unittest discover -s deploy/tests -v` (Python 3.12+).
- После успешной проверки не повторяй её без новых изменений, ошибок или конкретного сомнения.
  Перед завершением проверь diff; кратко сообщи результат и непроверенные ограничения.

## Короткий порядок деплоя

Автодеплой **установлен и проверен 2026-09-28**. Не настраивай его заново.
Подробные команды и восстановление: [deploy/README.md](deploy/README.md).

1. При запросе деплоя проверь нужные изменения, закоммить только файлы задачи и выполни
   `git push origin main`. Не включай чужие правки и не используй force-push.
2. `freelancenotify-deploy.timer` проверяет GitHub раз в 60 секунд. Скрипт собирает
   образ, запускает тесты, делает резервную копию и перезапускает бот с проверкой polling.
   Ошибка запуска возвращает предыдущие код и образ. GitHub Actions и новые секреты не нужны.
3. Дай время на проверку и сборку, затем одним SSH-вызовом проверь таймер,
   `/var/lib/freelancenotify-deploy/deployed.json` и состояние контейнера.
   Сверь deployed revision с отправленным SHA: одного успешного push недостаточно.
   Если сборка ещё идёт, читай короткий хвост журнала и жди, не опрашивай сервер каждую секунду.
4. Серверный checkout на конкретном SHA (detached HEAD) — штатный режим.
   Не делай вручную `git pull`, `checkout` или `docker compose up --build` поверх автодеплоя.
5. После изменения `deploy/deploy.py`, `deploy/install.sh` или unit-файлов нужна
   переустановка через `sh deploy/install.sh` на сервере после получения новой версии.
   Изменения README и тестов переустановки не требуют.
